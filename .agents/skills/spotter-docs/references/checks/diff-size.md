# diff-size

1 コミットの変更量（ファイル数・行数）に上限を設ける検査です。

コーディングエージェントは、頼まれた範囲を超えて書き換えることがあります。1 行直すつもりが
周辺を「ついでに整理」して数十ファイルに広がる、フォーマッタや一括置換が意図せず全ファイルに
走る、大量のファイルを削除する、などです。いずれも個々の変更は正しく見えるため、内容ベースの
検査（`diff-content` や `commit-intent` など）では捕まりません。**量**でしか捕まえられません。

## この検査の目的は「機械的な禁止」ではない

この検査の目的は変更量そのものを禁止することではなく、[免除トレーラ](../exemptions.md)を
通じて「なぜこの量になったか」を**人間に一度意識させる**ことにあります。`Diff-Size: skip
検査 API の一括リネームのため` のように理由を書かせることで、意図した大きな変更と、
意図しない暴走を区別できるようにします。上限そのものはプロジェクトの実情に合わせて
緩めに設定して構いません。

起動粒度は [per-commit](../granularity.md) 固定です。

## なぜ squashed ではなく per-commit なのか

squashed（範囲全体で合計）にすると、この検査は「PR 全体の大きさに上限を設ける」という
別の主張になってしまいます。それは「大きな PR は分割せよ」という話であり、この検査が
本来狙っている「**1 コミットの中で暴走が起きたこと**」とは別の関心事です。1 コミットの
中の暴走は、後から別のコミットを積んでも直りません（`unwanted-files` と同じ理由で
per-commit を選んでいます）。

## 設定

```yaml
checks:
  diff-size:
    type: diff-size
    max_files: 30
    max_lines: 800
    exclude:
      - '**/*.lock'
      - '**/vendor/**'
```

### `max_files`（省略可、既定 0 = 無効）

1 コミットで変更されたファイル数の上限。

### `max_lines`（省略可、既定 0 = 無効）

1 コミットで変更された行数（追加 + 削除の合計）の上限。

`max_files` と `max_lines` のどちらか一方は指定してください。両方 0（省略）だと
「常に成功する無意味な検査」になってしまうため、起動時エラーになります
（`unwanted-files` の `max_bytes` と同じ流儀）。

### `exclude`（省略可）

集計から除外するファイルの [doublestar](https://github.com/bmatcuk/doublestar) パターン
一覧（`doc-sync` の `exclude` と同じキーです）。

**既定値はありません。** ロックファイル名（`package-lock.json`・`go.sum` など）や依存
ディレクトリ名（`vendor/`・`node_modules/` など）は言語ごとに違うため、Go 側に
ハードコードせず利用者に書かせます。

## レシピ（設定例。既定値ではありません）

```yaml
# Node.js
exclude:
  - '**/package-lock.json'
  - '**/yarn.lock'
  - '**/pnpm-lock.yaml'
  - '**/node_modules/**'

# Go
exclude:
  - '**/go.sum'
  - '**/vendor/**'

# 生成コード全般
exclude:
  - '**/*.pb.go'
  - '**/*_generated.go'
```

## 集計方法

- 対象は `Source.Stats()`（`git diff --numstat` 相当）が返す全ファイル。`ChangedFiles()` と
  違い**削除されたファイルも含みます**（「大量削除」を捕まえるにはこれが必須です）。
- ファイル数は、`exclude` で除外した後に残ったファイルの件数です。
- 行数は、`exclude` で除外した後に残った各ファイルの追加行数 + 削除行数の合計です。
- バイナリファイルは行数の計上が 0 です（git の numstat がバイナリに対して行数を返さない
  ため）。ファイル数の計上には含まれます。
- リネームされたファイルは新パス側の 1 件として計上されます。

## 出力

```
diff-size の検査に失敗しました（a1b2c3d refactor: ...）。

  変更ファイル数が上限を超えています: 47 件（上限 30 件）
    - src/big.go (+320/-280)
    - src/other.go (+120/-40)
    - ...
    - ほか 42 件
  変更行数が上限を超えています: 1,203 行（追加 980 / 削除 223、上限 800 行）
    - src/big.go (+320/-280)
    - ...
```

超過したファイルを全部並べても読めないため、`Files` には変更行数の多い順に上位 5 件と
「ほか N 件」だけを表示します。同じ行数のファイルが複数ある場合、パス昇順で並ぶため、
出力は決定論的です。

## 免除

[免除トレーラ](../exemptions.md)が使えます。既定のトレーラ名は `Diff-Size` です
（キー名を変えていれば、そのキーから生成された名前になります）。per-commit 粒度なので、
免除トレーラは違反した**そのコミット自身**のメッセージに書く必要があります。

この検査はスコープ付き免除（`skip[対象] 理由`）には対応していません。角括弧付きで書くと
error になります。免除はいつも検査全体（そのコミットの違反すべて）が対象です。
