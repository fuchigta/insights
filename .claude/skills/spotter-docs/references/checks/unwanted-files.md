# unwanted-files

コミットしてはいけないもの（ローカルのデータベース・ログ・シークレット・巨大ファイルなど）の
混入を検知する検査です。

起動粒度は [per-commit](../granularity.md) 固定です。範囲内のコミットごとに 1 回ずつ見るため、
後から該当ファイルを消しても履歴には残った状態になり、検査は失敗し続けます。

## 設定

```yaml
checks:
  unwanted-files:
    type: unwanted-files
    max_bytes: 1048576
    deny:
      - { paths: '**/*.log', reason: 'ログファイル' }
      - { paths: '**/.env', reason: '環境変数・シークレット' }
      - { paths: '**/.env.*', reason: '環境変数・シークレット' }
      - { paths: '**/*.pem', reason: '秘密鍵' }
```

### `deny[].paths` / `deny[].reason`（両方必須）

拒否するファイルの [doublestar](https://github.com/bmatcuk/doublestar) パターンと、違反表示に
出す理由。両方無いと起動時にエラーになります。`deny` は上から順に評価し、最初に一致したルールの `reason` を
使います。

`*` は 1 階層しかまたぎません。`sub/a.log` のようにどの階層にあっても拾いたい場合は
`*.log` ではなく `**/*.log` と書いてください（`*.log` だと直下の `a.log` にしか一致せず、
`sub/a.log` は素通りします）。

`deny` は [`diff-content`](diff-content.md) と同じキー名を共用しています。`pattern`/`on`/`net`
は diff-content 専用のフィールドなので、unwanted-files の `deny` に指定すると起動時エラーに
なります。

### `max_bytes`（省略可、既定 0 = 無効）

これを超えるサイズの blob を含む変更を拒否します。`deny` のどのルールにも一致しなかった
ファイルだけがサイズ判定の対象になります（`deny` に明示的に載せたファイルは、理由も
`deny` 側のものが優先されます）。

**注意**：`deny` と `max_bytes` の両方が無い設定は起動時にエラーになります（常に成功してしまう
検査を防ぐため、どちらか一方は必ず指定してください）。

## 挙動の細部

- 対象は追加・変更・コピー・改名されたファイル（削除は対象外）です。
- ファイルサイズは、比較対象のコミット時点の blob サイズです（staged モードならステージ
  済みの中身、range モードなら比較先コミット時点の中身）。
- `deny` にも `max_bytes` にも触れなければ違反 0 件で成功します。

## 免除

[免除トレーラ](../exemptions.md)が使えます。既定のトレーラ名は `Unwanted-Files` です
（キー名を変えていれば、そのキーから生成された名前になります）。ただし per-commit 粒度
なので、免除トレーラは違反した**そのコミット自身**のメッセージに書く必要があります。
range モードで後続のコミットに書いても、既に履歴に残った違反コミットは免除されません。

## レシピ（設定例。既定値ではありません）

以下は「よくある違反パターンの書き方の例」であり、spotter が既定で持つ値ではありません。
必要なものだけを自分のプロジェクトの `.spotter.yml` にコピーして使ってください。

### 頼まれていない作業ファイル

コーディングエージェントが作業報告やコピーをそのままコミットしてしまうことがあります。

```yaml
- { paths: '**/*.{bak,orig,rej}', reason: '作業中のコピー・パッチの残骸' }
- { paths: '**/*_{old,new,backup}.*', reason: '古い版・新しい版のコピー' }
- { paths: '**/{IMPLEMENTATION,CHANGES,FIX}_*.md', reason: '作業報告のドキュメント' }
- { paths: '**/*_SUMMARY.md', reason: '作業報告のドキュメント' }
```

`SUMMARY.md` そのものは mdBook の目次などで正当に使われるため対象に入れていません。
`_v2` のような名前は API のバージョンとして正当に使われることがあるため対象に
入れていません。プロジェクトの実態に合わせて調整してください。
