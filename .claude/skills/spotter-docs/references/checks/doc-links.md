# doc-links

Markdown の**リンク記法**（`[text](target)`・画像・参照定義）が指すファイルの実在を
確認する検査です。

[`doc-paths`](doc-paths.md) は地の文に紛れた「コードへの言及」をバッククォートから拾う
検査で、誤検知を避けるために `path_prefixes` で強く絞り込む必要があります。この検査は
Markdown のリンク記法という明確な構文から拾うため、**絞り込みが要りません**。リンク先は
必ずパスです。抽出戦略も設定も違うため、`doc-paths` の拡張ではなく独立した type にして
います（共通処理は `internal/check/docutil` に切り出して両方から使っています）。

起動粒度は [worktree](../granularity.md) 固定です（`doc-paths` と同じ。免除トレーラは
持ちません）。

## 設定

```yaml
checks:
  doc-links:
    type: doc-links
    docs: ['**/*.md']
    ignore: ['docs/generated/**']
    check_anchors: false
```

### `docs`（省略可、既定 `**/*.md`）

対象ドキュメントの [doublestar](https://github.com/bmatcuk/doublestar) パターン一覧
（`doc-paths` と同じ既定）。

### `ignore`（省略可）

無視するリンク先の**完全一致**リスト。ここでの一致対象は、ドキュメント中に書かれている
生の文字列（`[text](target)` の `target` 部分そのもの。URL デコード前、`<>` を剥がす前）です。

### `check_anchors`（省略可、既定 `false`）

アンカー（`#見出し`）まで検証するかどうか。既定は **false** です。理由は、アンカー生成
規則が処理系依存（GitHub / GitLab / MkDocs で異なり、日本語見出しの扱いも違う）だからです。
既定で有効にすると誤検知が出て検査全体の信頼を損ないます。有効にする場合、この検査は
**GitHub の規則に準拠**したスラグ生成（近似）で判定します。

## 検証の対象

- インラインリンク `[text](target)` と画像 `![alt](target)`
- 参照定義 `[label]: target`
- タイトル付き `[text](target "タイトル")` はタイトル部を落として `target` だけを見ます
- `<target>` のように `<>` で囲まれた形は剥がしてから見ます

`<https://example.com>` のような自動リンクは対象外です（ほぼ外部 URL のため、`[]()` の
形を取るものだけを拾う実装上、自然に対象外になります）。

インラインコードスパン（`` `...` ``）の中身も対象外です。ドキュメントがリンク記法自体を
例示する際（このページの随所がそうであるように）、本物のリンクと誤認しないようにするため
です。フェンスドコードブロック内も同様に対象外です。

### 対象外にするもの（明確な非目標）

- `http://` `https://` `mailto:` などスキームを持つもの、プロトコル相対 `//host/...`
- **外部 URL への到達性確認は行いません。** ネットワークに出る検査は遅く不安定で、CI で
  偽陽性の原因になります。この検査はローカルの実在確認だけを扱います

## 相対パスの解決

リンク先は**そのドキュメントからの相対パス**です。`doc-paths` がリポジトリルート相対で
扱っているのと違うので注意してください。

- `docs/checks/doc-sync.md` の `[granularity](../granularity.md)` → `docs/granularity.md`
- 先頭が `/` のものはリポジトリルート相対として扱います（`/README.md` → `README.md`）
- `..` でリポジトリの外に出る場合は違反として報告します
- `%20` などの URL エンコードはデコードしてから実在確認します

## 抽出結果の確認

`spotter config explain <検査名>` で、対象ドキュメントごとに拾ったリンクと出現行、そして
外部リンク・`ignore`・空のリンクとして対象外になったか、どのパスに解決されたか（アンカー付き
なら併せて）を確認できます。リンク先の実在やアンカーの一致は判定そのものなので表示しません
（[config-reference.md](../config-reference.md)）。

## 出力

```
doc-links の検査に失敗しました。

  docs/checks/doc-sync.md がリンク切れを含んでいます:
    - ../granularity.md:12 → docs/granularity.md が存在しません
```

同じリンク先（生の文字列が完全一致）が同じドキュメント内で複数回出てきても、報告は
**最初に出現した行**の 1 件にまとめます（同じナビゲーションリンクがページごとに繰り返し
壊れているような場合に、同じ内容を大量に表示しないためです）。

## アンカー検証（`check_anchors: true`）

有効時の規則（GitHub 準拠）：

- 見出しのテキストを小文字化する
- 空白をハイフンに置き換える
- 英数字・非 ASCII 文字・ハイフン・アンダースコア以外の文字（句読点など）を除去する
- 同名の見出しが複数あれば、2 番目以降に `-1` `-2` ... を付与する

`path#anchor` の形では対象ファイルを読んで見出しを集めます。`#anchor` のみ（ファイル部分が
空）なら自分自身の見出しを見ます。コードフェンス内の `#` はコメント等であり見出しとして
数えません。

この実装は GitHub の規則の**近似**です。GitLab や MkDocs など他の処理系や、絵文字を含む
見出しなど一部のケースでは一致しない場合があります。誤検知が気になる場合は
`check_anchors` を無効のままにしてください。

## 免除

起動粒度が worktree のため、この検査には**免除トレーラの仕組みがありません**（コミット
メッセージにも git の差分にも依存しないため）。誤検知を抑えたい場合は `ignore` を使って
ください。

## この検査を他とどう噛み合わせるか

[doc-paths](doc-paths.md) との役割分担は次の通りです。

| | 拾う構文 | 絞り込み | リンク先 |
|---|---|---|---|
| `doc-paths` | バッククォート `` `...` `` | `path_prefixes` で強く絞る必要がある | パスとは限らない（コマンド名なども含む） |
| `doc-links` | Markdown のリンク記法 `[...]()` | 不要（構文自体が明確） | 必ずパス |
