# consistency

複数のファイルからそれぞれ独自の抽出規則で集合を取り出し、全ての組み合わせで一致するかを
検証する汎用検査です。「同じ情報を複数箇所に手で転記していて、片方だけ更新し忘れる」
（コミット type の一覧、対応バージョンの一覧、許可リストの重複管理など）を防ぎます。

起動粒度は [worktree](../granularity.md) 固定です。git の差分にもコミットメッセージにも
関わらず、現在の作業ツリーの中身だけを見るため、**免除トレーラを持ちません**。

## 設定

```yaml
checks:
  commit-types-consistency:
    type: consistency
    sources:
      - file: cliff.toml
        extract: 'message = "\^([a-zA-Z]+)"'
      - file: .spotter.yml
        extract: 'allowed_types:\s*\[(.*)\]'
        split: ','
```

`sources` は 2 つ以上必須です。各 `source` は `file`（1 ファイルを正規表現で行単位に
抽出する）か `glob`（ファイルパスの一覧を集合にする）のどちらか一方が必須です
（両方・どちらも無しは起動時エラー）。

### `sources[].file`（`glob` と排他）

抽出対象のファイル（リポジトリルートからの相対パス）。`./README.md` のように `./` を付けても、
`docs\a.md` のように `\` で区切っても、OS に関わらず同じファイルを指します。`../` や絶対パス
（`/` やドライブ文字 `C:` で始まるもの）でリポジトリの外を指すと起動時エラーになります。

### `sources[].line`（省略可、`file` 専用）

この正規表現にマッチする行だけを抽出対象にします。省略時は全行が対象です。`glob` との
併用は起動時エラーです。

### `sources[].until`（省略可、`file` 専用）

指定すると、`line` にマッチした行から `until` にマッチする行まで（両端含む）を
1 ブロックとしてまとめ、ブロック内の**各行**に `extract`（さらに `split`）を当てます。
複数行に折り返した YAML の配列などをまとめて拾いたい場合に使います。複数ブロックが
あれば全て対象になります。`until` の探索はブロック開始行の**次の行から**始めるため、
`line` と `until` が同じ書き方（例: どちらも「行頭が非空白」）でも開始行自身が終端と
みなされることはありません。**`line` とセットでのみ指定できます**（`line` を省略した
状態で `until` だけを指定すると起動時エラー）。ブロックの開始（`line` にマッチした行）が
見つかったのに、ファイル末尾まで `until` にマッチする行が現れなければ実行時エラーに
なります。構造化データ（YAML/JSON のパス指定）そのものを解釈するものではなく、あくまで
行ベースの範囲指定です。

### `sources[].extract`（`file` を使う場合は必須、`glob` では省略可）

`file` では対象行に適用する正規表現。**キャプチャグループがちょうど 1 つ必須**です（0 個や 2 個以上は
起動時にエラー。値として取り出さないグループが要るときは `(?:...)` を使ってください）。
1 行に複数マッチすれば全て集合に加えます。`glob` で使う場合は `sources[].glob` の節を
参照してください。
正規表現を YAML に書くときのクォートは [config-reference.md](../config-reference.md#yaml-に正規表現を書くときの注意) を参照してください。

### `sources[].split`（省略可、`file` 専用）

指定すると、`extract` で捕まえた文字列をさらにこの区切り文字で分割し、前後の空白を
トリムした上でそれぞれを要素として集合に加えます。「`[feat, fix, docs]` のような 1 行の
配列表記」から個々の要素を取り出したい場合に使います。`glob` との併用は起動時エラーです。

### `sources[].subset`（省略可、既定 `false`）

`true` にすると、この source は「他の（`subset` ではない）source の和集合に無い要素を
持ってはいけないが、要素が欠けていても違反にならない」対象になります。`subset` ではない
source どうしは従来どおり完全一致が要求されます。`subset` ではない source が 1 つも無い
設定は起動時エラーです（比較の基準が無くなるため）。「一部のファイルは全体の一部だけを
転記している」構成（例: README の抜粋表）を扱いたい場合に使います。`file` / `glob`
どちらの source でも使えます。

### `sources[].glob`（`file` と排他）

リポジトリルート配下でこの doublestar パターンに一致する**ファイル**のパスをそのまま
要素の集合にします（ディレクトリ、`.git` 配下は含めません）。パス区切りは Windows でも
`/` に揃います。`line` / `until` / `split` とは併用できません（指定すると起動時エラー）。
「抽出規則というより、ファイルの集合そのものを突き合わせたい」場合（例: `docs/**/*.md` の
ページ集合と、目次のリンク集合の突き合わせ）に使います。

`extract` を併用すると、`base` を取り除いた後の各パスにその正規表現を当て、キャプチャ
グループ 1 を要素にします。拡張子を外して `- id: analytics` のような ID と突き合わせたい
場合（`'^(.+)\.md$'`。`frontend/html.md` は `frontend/html` になります）に使います。
キャプチャグループがちょうど 1 つ必要な点は `file` と同じで、満たさなければ起動時
エラーです。一致しないパスは実行時エラーにします（黙って捨てると、意図しないファイルの
混入に気付けなくなるため）。

```yaml
checks:
  docs-index-consistency:
    type: consistency
    sources:
      - glob: 'docs/**/*.md'
        base: docs
        exclude: ['docs/README.md']
      - file: docs/README.md
        extract: '\]\(([^)#]+\.md)\)'
```

### `sources[].base`（省略可、`glob` 専用）

`glob` が一致したパスから、この接頭辞ディレクトリを取り除いた相対パスを要素にします
（例: `base: docs` なら `docs/checks/a.md` は `checks/a.md` になります）。`base` 配下に
無いパスが一致した場合は実行時エラーです（黙って無視すると、意図しない場所の一致に
気付けなくなるため）。`file` との併用は起動時エラーです。

### `sources[].exclude`（省略可、`glob` 専用）

指定した doublestar パターンの一覧のいずれかに一致するパスを、`glob` の一致結果から
除外します。パターンは `base` を取り除く**前**のルート相対パスに当てます。`file` との
併用は起動時エラーです。

## 挙動の細部

- `sources[].file` が存在しなければ、どの `sources` の何番目がどのファイルを指しているかを
  含めたエラーにします。
- 各 `source` から抽出した集合が **1 つも要素を持たなければエラー**にします（0 件は
  「抽出規則やパスの構成がファイルの実体に追従できていない」可能性が高いため、静かに
  素通りさせずに気付けるようにしています）。`glob` が 1 件も一致しない場合も同じ扱いです。
- `subset` ではない source どうしで、一方にしかない要素があれば違反にします。`subset` な
  source は和集合に無い要素を持っている場合だけ違反にし、欠けていることは違反にしません。
- 食い違いは 1 つの違反としてまとめ、食い違う要素ごとに 1 行を報告します
  （例: `` `feat`: README.md に無い（cliff.toml, .spotter.yml にある） ``）。要素・
  ファイルの順序はソートするため、実行するたびに同じ表示になります。`glob` な source の
  表示名にはファイルパスではなく glob パターンそのものを使います。

## 抽出結果の確認

`spotter config explain <検査名>` で、source ごとに `line` / `until` が見たブロックの行範囲と、
`extract`（・`split`）で取り出した要素と出現位置（`glob` ならパス）を、合否を付けずに
確認できます。`subset` の source が想定より少なくても通ってしまう場合や、0 件エラーで
どこまで見ていたか分からない場合に使います（[config-reference.md](../config-reference.md)）。

## 書き方のコツ

- `extract` は「型を保証する記法」を狙って書くと安全です。例えば TOML の
  `message = "^feat"` のような行なら、ダブルクォートまで正規表現に含めることで、
  シングルクォートで書かれた例外行（`skip = true` の行など）を自然に除外できます。
- 抽出対象は `.spotter.yml` 自身でも構いません。設定ファイル自体を「突き合わせ元」に
  含めることで、他のファイルとの二重管理をこの検査だけで検知できます
  （上の例がまさにそれです）。
